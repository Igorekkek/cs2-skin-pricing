# 03 · Сжатие модели: от 8 ГБ до мегабайтов

**Вопрос.** Исходная модель CatBoost (три модели: одна для оценки и две для краёв вилки,
настройки по умолчанию) занимала на диске 8–9 ГБ. 99,96% этого объёма приходилось на
CTR-таблицы, о них ниже. Такую модель невозможно выложить на GitHub или дёшево запустить
на сервере. Насколько её можно уменьшить и чего это стоит в точности?

**Что такое CTR-таблицы.** CatBoost превращает категории (название скина, номер
наклейки) в числа: для каждого значения он запоминает статистику, например среднюю
наценку. По умолчанию он делает то же для *сочетаний* категорий, скажем «скин + наклейка
в слоте 1». Для каждого встреченного сочетания хранится своя строка статистики, и если
сочетаний миллионы, таблицы разрастаются до гигабайтов.

**Рычаги.**

* `max_ctr_complexity` — сколько категорий CatBoost может объединять в одно сочетание
  (по умолчанию 4). Значение 1 означает «без сочетаний».
* `quantile_mode` — три отдельные модели или одна модель `MultiQuantile` с тремя
  выходами (q15, q50, q85) на общих деревьях.
* Признак `skin_seed_key` («скин + номер паттерна»).

**Метод.** Признаки и разбиение такие же, как во всех остальных экспериментах; меняются
только эти параметры. Размер — суммарный объём сохранённых файлов модели.

**Запуск.** `python experiments/03_model_compression/run.py`. Результаты кэшируются,
`--only multi_ctr1,multi_ctr2` обучает только перечисленные варианты.

## Результат

| вариант | признак «скин + паттерн» | медианная ошибка | средняя ошибка | цена в 70%-вилке | размер |
|---|---|---|---|---|---|
| исходная конфигурация: 3 модели, сочетания до 4 категорий | да | (4,85%\*) | | | **8 ГБ**\* |
| MultiQuantile, сочетания до 2 категорий | да | **4,90%** | $1,36 | 68,0% | 3 745 МБ |
| MultiQuantile, без сочетаний | да | 5,04% | $1,44 | 65,3% | 36 МБ |
| MultiQuantile, сочетания до 2 категорий | нет | 5,01% | $1,38 | 66,2% | 129 МБ |
| **MultiQuantile, без сочетаний** | **нет** | 4,96% | $1,38 | 65,9% | **6,2 МБ** |
| 3 отдельные модели, без сочетаний | нет | 4,93% | $1,40 | **69,5%** | 9,2 МБ |

\* Из исходного отчёта. Там модель оценивалась на старом коде: обучение останавливалось
по тестовой выборке, а среди признаков было число наблюдающих за лотом, записанное уже
после продажи. Поэтому напрямую эти числа сравнивать нельзя. Переобучение этой
конфигурации здесь занимает около 3 часов и запускается флагом `--slow`.

## Вывод

* Почти весь размер дают таблицы *сочетаний* категорий, и раздувает их один признак.
  У `skin_seed_key` (скин + номер паттерна) 429 тысяч разных значений на 575 тысяч строк
  обучения, то есть он почти уникален для каждой продажи. Без него модель становится
  в 6 раз меньше *и* чуть точнее. Информация о паттерне при этом не теряется: её несёт
  признак `seed_past_premium` (прошлые наценки этого паттерна, посчитанные без
  подглядывания в будущее).
* Сочетания из двух категорий дают 0,06 п.п. точности ценой модели в 600 раз больше.
  Оно того не стоит.
* Одна модель MultiQuantile вместо трёх весит втрое меньше и обучается втрое быстрее при
  той же точности оценки, но её вилка хуже откалибрована на тесте: 66% вместо 69,5% при
  цели 70%. Отдельные модели остаются доступны (`quantile_mode = "separate"`).
* **Выбрано по умолчанию: MultiQuantile, без сочетаний, без признака «скин + паттерн».
  6,2 МБ вместо 8 ГБ.** Такую модель можно приложить к релизу на GitHub и загрузить за
  секунду.

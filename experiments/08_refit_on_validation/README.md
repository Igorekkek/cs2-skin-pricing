# 08 · Использовать дни валидации для финального обучения

**Вопрос.** Валидационная выборка нужна, чтобы вовремя остановить обучение и
откалибровать вилку. Но здесь это четыре дня прямо перед тестом, и в них 82 тысячи самых
свежих продаж. Поможет ли дообучить модель на обучении и валидации вместе, сохранив число
деревьев или эпох, выбранное по валидации?

**Метод.** Для каждой обучаемой модели сравниваются модель из эксперимента 02 (обучена
только на обучающей выборке) и та же конфигурация, переобученная на обучении + валидации.
Калибровку вилки берём у первой модели: по данным, которые переобученная модель уже
видела, вилка получилась бы слишком узкой.

**Запуск.** `python experiments/08_refit_on_validation/run.py` (после эксперимента 02).

## Результат

| модель | медианная ошибка: только обучение → с валидацией | средняя ошибка | цена в 70%-вилке |
|---|---|---|---|
| premium_catboost | 4,96% → 4,89% | $1,38 → $1,40 | 65,9% → 67,4% |
| target_encoded_hgb | 4,65% → **4,60%** | $1,37 → $1,36 | 71,1% → 70,1% |
| quantile_mlp | 4,67% → 4,66% | $1,42 → $1,53 | 69,0% → 67,9% |

## Вывод

Бустингам переобучение даёт небольшое, но стабильное улучшение (−0,05..−0,07 п.п.),
нейросети ничего, а её долларовая ошибка даже растёт. Повторить то же число эпох и то же
расписание скорости обучения на 14% большем объёме данных — уже другая задача
оптимизации, а без валидации нечем определить момент остановки. В сервисе используются
переобученные версии только двух бустингов.

Четыре дня самых свежих продаж стоят меньше, чем можно было бы ожидать. Вероятная причина
(не проверялась): признаки истории рынка и так передают модели, обученной на более старых
строках, актуальное состояние рынка.
